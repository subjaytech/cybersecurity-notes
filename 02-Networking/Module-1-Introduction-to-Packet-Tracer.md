# Module 1 - Introduction to Cisco Packet Tracer

## Overview

This module introduced Cisco Packet Tracer, a network simulation tool used to design, configure, and troubleshoot computer networks in a virtual environment.

The objective was to become familiar with the Packet Tracer interface and understand how logical and physical network representations relate to one another.

---

## Learning Objectives

By the end of this module, I was able to:

- Navigate the Cisco Packet Tracer interface.
- Identify common networking devices.
- Understand the difference between Logical and Physical workspace.
- Connect devices using appropriate network cables.
- Complete a basic Packet Tracer activity.

---

## Cisco Packet Tracer Interface

The Packet Tracer workspace contains several components that support network design and simulation.

### Common Devices

- Routers
- Switches
- Hubs
- PCs
- Laptops
- Servers
- Wireless Devices
- IP Cameras

---

## Logical Workspace

The Logical Workspace focuses on how devices communicate within a network.

It provides a simplified view of:

- Device placement
- Network topology
- Connections between devices
- Data flow

This view is primarily used for designing and troubleshooting network communication.

---

## Physical Workspace

The Physical Workspace represents how the network exists in the real world.

It includes:

- Buildings
- Wiring closets
- Equipment racks
- Physical cable connections
- Geographic locations

This helps visualise how logical designs translate into actual infrastructure.

---

## Logical vs Physical Mode

| Logical Mode | Physical Mode |
|--------------|---------------|
| Shows network topology | Shows physical layout |
| Focuses on communication | Focuses on equipment placement |
| Easier for designing networks | Easier for understanding deployment |

## Challenge Encountered

While completing the activity, I accidentally connected one laptop directly to another instead of connecting it to the backup router.

After identifying the mistake, I restarted the activity and rebuilt the network using the correct topology.

This reinforced the importance of verifying network connections before deployment.
